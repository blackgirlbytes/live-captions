**How it behaves**
- **Your own key:** the key is stored in `chrome.storage.local` under `deepgramKey`. When you press Start, the background reads it and passes it to the offscreen document in the start message; that is the only message that carries it. The offscreen document then connects to Deepgram directly. A saved key always wins, and the Earshot server is never contacted.
- **Server mode:** with no key saved, the background first checks the server with `GET /api/deepgram/token`, then uses the existing token fetcher. If the server is unreachable or reports `serverKey:false`, Start fails straight away with a "needs a Deepgram API key" message and an "Add your Deepgram key" button, without starting capture.
- **Side panel:** the tab is now called "Settings". A "Deepgram key" section sits above Server URL with everything you specified: password field with Show/Hide, "Verify &amp; save", inline errors, "Forget key", the status line, the console link with the dedicated-key advice, and the privacy line. When no key is available, a "needs a key" notice appears at the top.
- **Popup:** shows the same "needs a key" notice. "Add your key" opens the side panel on the key field. "Open Earshot web" is hidden when there's no server or you're using your own key.
- **"API key" errors:** if a session fails with one, both popup and side panel show "Check your key".
